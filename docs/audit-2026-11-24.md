# IndoorID accessibility and ease-of-use audit

Audit of `mglsj/indoor-id` at `1ccf84a` (after P6), 24 November 2026. No code was changed.

## How this was tested

- The dev server, driven by Playwright in Chromium at 1440×900 (desktop) and 390×844 (phone), in the light and the dark theme.
- Real OpenStreetMap data: Centre Commercial Grand Quartier in Rennes (`w63904146`), two levels and about 60 shops.
- axe-core 4.10 on every screen state, plus my own contrast measurements: the theme tokens as the browser resolves them, the map colours from `style/colors.ts` and `layers.ts` against the basemap's real pixels, and a deuteranopia simulation (Machado matrix).
- Target: good practice, using WCAG 2.2 AA numbers as a yardstick, not a formal conformance claim. The editor is desktop only; the viewer should also work on a phone (both confirmed on 24 November).
- Limits: Overpass and Esri imagery could not be reached from my sandbox, so the viewer showed no data and I couldn't screenshot imagery. The contrast on imagery uses a sampled dark aerial tone (`#3e463a`) and is an estimate.

Screenshots are numbered as the report cites them. They are kept with the project files (`a11y-audit/`), not in the repository.

## Decisions (24 November)

Your answers to the questions, and the layout you chose. Where this section and a finding below disagree, this section wins.

1. **The editor is desktop only.** Phone findings for the editor are dropped. The viewer's phone layout (E) stays.
2. **Good practice, not formal conformance.** The ratios below still use WCAG's 3:1 and 4.5:1 as the bar, because they are the easiest way to say "visible". Nothing needs an audit trail.
3. **Moving off shadcn's stock tokens is fine.** So A1 to A3 become token changes in `app.css` rather than per-component overrides. Starting values:

   | Token                                    | Light now → proposed             | Dark now → proposed       | Result                                                                     |
   | ---------------------------------------- | -------------------------------- | ------------------------- | -------------------------------------------------------------------------- |
   | `--ring`                                 | 0.708 → **0.45**                 | 0.556 → **0.70**          | Focus ring about 7:1 light, 6:1 dark; draw it at full strength, not `/50`  |
   | `--input`                                | 0.922 → **0.70**                 | 15% white → **35% white** | Field and checkbox outlines about 3:1                                      |
   | `--muted-foreground`                     | 0.556 → **0.50**                 | 0.708 (keep)              | Secondary text ≥5:1 on `muted` too                                         |
   | New `--pressed` / `--pressed-foreground` | `primary` / `primary-foreground` | the same                  | Pressed tools and selected levels and toggles at 14–17:1 instead of 1.09:1 |

   `--border` stays light, for dividers only.

4. **Layout:**
   - **Place search moves into the header.** It sits between the page links and Licenses, and is the same on the editor and the viewer.
   - **Floor plans moves to the right column, right under Background,** and its panel opens in the right-hand pane like Background and Guides, no longer in the left side panel.
   - **The building pill ("Inside … · Done") moves to the bottom middle of the map.**

### What the layout decisions imply

The new right column is, top to bottom: Background, Floor plans, Guides, then the level switcher. The left column keeps the tools only: history and Save, draw, snap/grid and the selection operations.

```
┌ Header: IndoorID · Edit View Help · [Search a place ……] ······ Licenses · Language · Theme ┐
├ Side panel ┬──────────────────────────────────────────────────────────┬ Right pane (320px) ┤
│ Inspector  │ ↶ ↷ Save ⚠  ?                         [Background]       │ Background, or     │
│ / Building │ Point Line Area Rect Split Measure    [Floor plans]      │ Floor plans, or    │
│ / Floor    │ Snap Grid ▾                           [Guides]           │ Guides             │
│            │ (selection operations)                [Level switcher]   │                    │
│            │                                                          │                    │
│            │          (tool hint pill)                                │                    │
│            │   [Inside Centre Commercial Grand Quartier · Done]       │                    │
└────────────┴──────────────────────────────────────────────────────────┴────────────────────┘
```

Things to settle while building it:

- **The bottom middle is already busy.** Tool hints sit at `bottom-20`, and the load status ("Zoom in to load…", "Some data could not be loaded") at `bottom-10`, both centred. Make one bottom-centre stack: the building bar lowest, the load status above it, the tool hint above that, so they never overlap. Keep the stack clear of the attribution, which spans most of the bottom right at 1440px.
- **"Edit indoor" and "Edit indoor here" should move with it,** so entering and leaving a building happen in the same spot. Today they sit where the pill does.
- **The Floor plans pane gets 320px instead of the side panel's 352px (and resizable) width.** `PlanList` rows and `PlanTools` (the alignment controls) were laid out for the wider panel, so they need a pass at 320px, or the right pane could become resizable too.
- **Floor plans and the inspector can now be open at once.** Today plan mode replaces the inspector and hides the drawing tools. With plans on the right, you could keep a plan's controls open while tracing on the left, which is better for tracing. A plan's alignment session still needs to block drawing while it's active.
- **Only one right pane is open at a time,** so opening Floor plans closes Background or Guides. That's the current behaviour for the other two, and it seems right.
- **The search box in the header needs a width limit** (about 18rem), and on a phone, in the viewer, it should collapse to an icon that opens it full width. That also fixes the overlap in screenshot 25.
- **Make building mode unmistakable.** You asked about this on 24 November because the pill looks like any other control. **Decided: all six points below.**
  - A **mode bar** at the bottom middle, filled with a new accent `--mode` token (an indigo or blue, not the neutral grey), white text, a building icon, the building's name, the shown level, and a filled **Leave building** button with an `Esc` key cap.
  - A **3px inset frame** in the same accent around the map while inside, so the whole viewport says "you're in a building", as Figma's isolation mode does. The existing fade of the surroundings stays.
  - **Rename "Done" to "Leave building"** (or "Exit indoor"). "Done" reads like "save my work", and leaving doesn't upload anything.
  - The **header breadcrumb**: "Edit › Centre Commercial Grand Quartier ×", so the mode is visible even when the map is covered.
  - A **one-time hint on entering**: "You're editing inside Grand Quartier. Leave building or Esc returns to the map." It shows the first few times, then stops.
  - The side panel's building header picks up the same accent stripe, so the panel and the bar read as one mode.
- Save and Issues weren't part of your answer, so they were settled on 25 November (below).

## Decisions (25 November)

1. **Save and Issues move to the right side of the header,** before Licenses, Language and Theme. Save becomes the filled primary button once there are edits.
2. **Selection operations become a contextual bar.** It shows six labelled actions (Delete, Copy, Square, Merge, Repeat on levels, Split), with the rest under "More ▾" and the precise transforms under "Transform ▾". The right-click menu gets the same grouping (B2).
3. **A new "Map data" pane** goes in the right column. Area fill and Highlight changes move into it from Background, and it holds the appearance settings below.
4. **New default colours** that are visible on the light map and safe for colour-blind users, for the grid, the selection and Highlight changes. iD's colours stay available as an option.
5. **The building-mode accent is blue,** as a new `--mode` token used only for building mode (mode bar, map frame, panel stripe).
6. **The Level field is pinned right under the preset** in the inspector, for every feature.
7. **Units keep following the browser's language.**
8. **No new features.** Only the quality-of-life items that build on existing features and are small changes:
   - **Appearance settings in Map data:**
     - Grid colour and opacity, which you asked for.
     - The default colour for new guides (the per-guide colour already exists).
     - The selection colour.
     - The Highlight-changes palette.
   - **A Zoom to selection button** in the selection bar. Z already does this.
   - **Undo and Redo tooltips name the step,** for example "Undo: Square the corners". History steps already have labels.
   - **PageUp and PageDown change level,** the same as the level switcher's arrows.
   - **Inspector sections remember being open or closed,** and Measurements starts open.
   - **A search box in the shortcuts dialog,** filtering the existing list.
   - **An icon placeholder** for presets without one, so names line up.

   Dropped for now: the command palette, the status bar, vertex and label size, floor plan tint, basemap dimming, UI density, the high-contrast mode (the token changes cover it), recent tags, the first-run tour, saved views per building, and the undo history list.

## The short version

axe-core found almost nothing in the DOM. The only hits were three unnamed offset inputs in the Background pane and popovers outside a landmark. The labelling work (aria-labels, tooltips with shortcuts, `role=status` hints, the shortcut list taken from the keymap) is good.

The real problems are the ones axe can't see:

1. **"On" and "off" look the same.** A pressed toolbar button, a selected level and a selected toggle differ from their neighbours by 1.09:1 in light and 1.31:1 in dark. WCAG asks for 3:1. You can't tell whether snapping or the grid is on (09, 10, 11).
2. **The map's working colours are faint on the light basemap.** The grid draws at 1.23:1 (minor lines) and 1.66:1 (major lines). The selection's amber draws at 1.78:1, and snap guides at 2.87:1. iD's "Highlight changes" colours draw at 1.05 to 2.1:1 because they were designed for dark imagery. None of these can be changed, except a guide's colour.
3. **The selection colour, "reshaped" and "retagged" look the same to colour-blind users.** Under deuteranopia, amber `#f59e0b`, orange `rgb(255,126,46)` and yellow `#fcde5a` all become one yellow. Reshaped vs selection is 1.18:1 even with normal vision.
4. **Focus rings are barely visible in light mode.** The ring is `ring/50`, which draws at 1.54:1 on white (21–23).
5. **The left column of floating toolbars has grown to seven rows,** and they move. The row count changes with the mode, and rows jump down when the Measure/Guide toggle appears. The selection row has 14 unlabelled icons. Tool groups don't follow a clear order (02, 04, 13).
6. **The right-click menu doesn't fit the screen.** It scrolls with no scroll cue, and Delete, the most used item, is last and off-screen (05).
7. **The Level field sits at the bottom of the inspector,** under Website and Brand, in an editor whose whole subject is levels (18).
8. **The level switcher shows the current level twice** ("0" above the list, then "0" in it) (11).
9. **The keyboard order doesn't match the screen.** From the header, Tab goes to the map, then the zoom buttons and attribution (bottom right), then the side panel, then the toolbars. That's about 40 stops to get from one side to the other, with no skip links and no roving focus inside toolbars.
10. **Phones (viewer only):** the header runs off the screen (the theme button can't be reached), and the viewer's search box sits on top of the Background button (24, 25).

## Findings

Priorities: **P1** blocks or seriously slows some users, or fails WCAG AA. **P2** clear friction, worth doing soon. **P3** polish.

### A. Colour and contrast

#### A1 (P1). Pressed and selected states are invisible (WCAG 1.4.11)

| State cue                                                     | Light                        | Dark                         |
| ------------------------------------------------------------- | ---------------------------- | ---------------------------- |
| `secondary` (pressed tool, snap/grid on) vs `background`      | #f5f5f5 / #ffffff **1.09:1** | #262626 / #0a0a0a **1.31:1** |
| `muted` (selected level row, selected toggle) vs `background` | **1.09:1**                   | **1.31:1**                   |
| `accent` (hover, active preset row) vs `background`           | **1.09:1**                   | **1.31:1**                   |

Screenshots 09 to 12: snapping and the grid are both on in 09, and the selected level is 0 in 11.

Fix: give pressed and selected items a cue that doesn't depend on the fill. Options are an inset 2px `foreground` ring or underline, an inverted fill (`bg-primary text-primary-foreground`, 17:1), or a check or dot. The theme rule says not to hand-edit shadcn, so this means adding a `pressed` style (or a `data-[state=on]` style in `app.css`) used by `toggle`, `toggle-group` and the `variant={on ? "secondary" : "outline"}` buttons.

#### A2 (P1). Focus ring too faint in light mode (WCAG 2.4.7, 2.4.13)

|                                          | Light              | Dark               |
| ---------------------------------------- | ------------------ | ------------------ |
| `ring` solid (the border shown on focus) | #a1a1a1 **2.58:1** | #737373 4.18:1     |
| `ring/50` (the 3px halo)                 | #d0d0d0 **1.54:1** | #3f3f3f **1.88:1** |

Links (Licenses, attribution) get a 1px grey outline (21, 22). Fix: use `--ring` at `oklch(0.45 0 0)` in light mode (about 7:1) and draw the halo at full strength, or add a 2px `outline-offset` outline in `foreground`. The MapLibre controls already draw a blue 2px ring, which looks inconsistent next to the grey one.

#### A3 (P2). Theme tokens: text is fine, borders are faint

| Pair                                                                      | Light    | Dark     | AA                  |
| ------------------------------------------------------------------------- | -------- | -------- | ------------------- |
| Body text                                                                 | 19.8     | 19.0     | ✓                   |
| Secondary text `muted-foreground` on `background`                         | 4.74     | 7.66     | ✓ (just)            |
| `muted-foreground` on `muted` (descriptions inside selected rows, badges) | **4.35** | 5.86     | ✗ light, small text |
| Destructive text                                                          | 4.77     | 6.85     | ✓                   |
| Input and checkbox outline (`input`)                                      | **1.26** | **1.48** | ✗ 1.4.11            |
| Card and panel borders (`border`)                                         | 1.26     | 1.26     | decorative, OK      |

Input borders are what tell people a field is there. The empty Building field and the Add… combos in the inspector (04, 18) are nearly invisible boxes. Raising `--input` to about `oklch(0.70 0 0)` in light mode gives 3:1. Keep `--border` light for dividers.

Muted text at 4.35:1 inside selected rows fails at 12–14px. Darken `--muted-foreground` to `oklch(0.50 0 0)` (about 5.6:1 on white, 5.2:1 on muted).

Also: the version string and the `text-xs` helper text (11–12px grey) are legible but small. The "Only imagery can be moved" disabled block is about 2:1. Disabled items are exempt from WCAG, but it reads as broken.

#### A4 (P1). Map working colours on the light basemap

Contrast against the basemap inside a building (`#eaeae5`), white, and a dark aerial (estimate):

| Map element                                                | Basemap  | White | Dark imagery |
| ---------------------------------------------------------- | -------- | ----- | ------------ |
| Grid, minor (`#d946ef` at 0.18)                            | **1.23** | 1.25  | 1.15         |
| Grid, major (`#d946ef` at 0.45)                            | **1.66** | 1.77  | 1.51         |
| Snap guides, construction guides (`#d946ef`, 1.5px dashed) | **2.87** | 3.46  | **2.84**     |
| Selection (`#f59e0b`)                                      | **1.78** | 2.15  | 4.56         |
| Highlight changes, added                                   | **1.05** | 1.27  | –            |
| Highlight changes, retagged                                | **1.11** | 1.33  | –            |
| Highlight changes, reshaped                                | 2.10     | 2.54  | –            |
| Room outline `rgb(125,125,125)`                            | 3.41     | 4.12  | **2.38**     |
| Vertex stroke `#757575`                                    | 3.82     | 4.61  | **2.13**     |
| Door green (viewer) `#00ab0d`                              | **2.55** | 3.07  | 3.19         |

Graphics need 3:1. In practice:

- **The grid** reads as a faint pink haze (07, 08). It also uses the same magenta as snap guides and construction guides, so an angle guide disappears into the grid when both are on.
- **The selection** is held up by its 2px width and its white vertices, but the amber band on a light floor is weak (04).
- **Highlight changes** was copied from iD, whose map is dark imagery. On this always-light basemap, "added" green and "retagged" yellow can't be seen.
- **On imagery** the editor's greys (rooms, vertices) drop to about 2:1. Map labels are fine on the basemap (10:1) and depend on their white halo on imagery.

#### A5 (P1). Colour-blind safety

Deuteranopia simulation:

| Colour                             | As seen          |
| ---------------------------------- | ---------------- |
| Selection `#f59e0b`                | `#d0b914` yellow |
| Reshaped `rgb(255,126,46)`         | `#c2ae2a` yellow |
| Retagged `#fcde5a`                 | `#fbe361` yellow |
| Added `rgb(133,255,103)`           | `#f5e073` yellow |
| Stairs / vertical `rgb(80,165,45)` | `#9f9039` olive  |
| Building `rgb(205,85,70)`          | `#928543` olive  |
| Space `rgb(176,150,100)`           | `#a89c65` olive  |

So with Highlight changes on, a selected room, a reshaped room and a retagged room look the same. Buildings, stairs and spaces also fall together. Fixes:

- Draw the selection with a second cue that isn't a hue: a double line (dark core plus light casing), or a dashed halo.
- Use a different line pattern for each edit kind (solid, dashed, dotted).
- Offer a colour-blind-safe palette (see QoL).

#### A6 (P3). Colour use in the UI

- The issues count uses `text-destructive` for warnings. Warnings and errors should differ (yellow triangle vs red).
- The status pill turns red for load errors with no icon. Add an icon so the meaning doesn't rest on colour alone (1.4.1).

### B. Tool organisation and layout

#### B1 (P1). The left column is overloaded and moves

At 1440×900, with a building entered and a room selected, the left column stacks seven floating rows (04). Problems:

- **It shifts.** Picking Measure inserts the Measure/Guide row and pushes snapping and Floor plans down (13). Selecting something inserts a 14-icon row. Resizing the side panel moves the whole column. Muscle memory never settles.
- **The grouping doesn't match how the tools are used.** Undo, Redo and **Save** share a group, so Save looks like a history action. The Keyboard shortcuts button gets a group of its own in the middle of the tools. Floor plans, a whole mode, is a lone button under the selection operations.
- **Split (X) and Measure (M) sit with the draw tools.** Split acts on the selection, and Measure is a precision aid.
- **Building tools appear and disappear without notice.** Rectangle, Split and Measure only show inside a building. Nothing outside a building tells you that more tools exist (01 vs 02).

My first sketch is below. The layout in **Decisions** replaces it where they differ (search in the header, Floor plans on the right, the building bar at the bottom).

First sketch:

```
┌ Header: IndoorID · Edit View Help ······ [Save ▲ 3] [⚠ 2] · Language · Theme · ? ┐
├ Side panel ┬ Top bar (fixed, one row, one height): ────────────────────────────────┤
│            │ [Search place]  │ ↶ ↷ │ Point Line Area Rect │ Measure ▾ │ Snap ▾ Grid │
│ Inspector  │ Building pill: "Inside Grand Quartier · Level 0 · Done"              │
│ / Building │                                               Background  Map data  │
│ / Plans    │                                               Guides      Plans     │
│            │        (map)                                       Level switcher    │
│            │   ┌ Selection bar, floating above the selection or docked bottom: ┐  │
│            │   │ Copy · Delete · Square · Merge · Repeat on levels · More ▾      │  │
│            │   └─────────────────────────────────────────────────────────────────┘  │
└────────────┴──────────────────────────────────────────────────────────────────────┘
```

- **Save and Issues go to the header, on the right,** as in iD and JOSM. Save becomes the primary filled button (`bg-primary`) once there are edits.
- **One fixed top bar of tools** that never changes height. Building-only tools stay visible but disabled outside a building, with a tooltip like "Enter a building to draw rectangles". The Measure/Guide toggle becomes a split button ("Measure ▾ / Guide"), not a new row.
- **Selection operations go into a contextual bar**, with the 4–6 common ones labelled and the rest under "More ▾". The common ones are Delete, Copy, Square, Merge, Repeat on levels and Split. The precise transforms (move, rotate, scale, side, offset, square to frame, straighten, symmetric) become a "Transform ▾" submenu.
- **Floor plans moves to the right column** with Background, Guides and a new "Map data" pane.
- **The keyboard button goes into the header as "?"**, next to Help.

#### B2 (P1). Right-click menu overflows and is in the wrong order (05)

The menu holds 14 items in 516px, but only 446px fit below the click. It scrolls silently, and **Delete** is the last item, below the fold. Fixes:

- Group the items with separators: edit (copy, paste, delete) / shape (square, straighten, symmetric, merge, split) / levels (repeat, cut out) / transform ▸ submenu.
- Put Delete in a fixed spot (iD puts it last, but its menu is short).
- Let the menu flip upward when there's more room above (bits-ui `collisionPadding` / `avoidCollisions`).
- Show disabled items with their reason inline, not in a `title` tooltip that keyboard users never see.

Note: while the menu was open, a blank rectangle the width of the menu covered the map above it (05, white in light mode, black in dark). It also appeared above the snap popover (06). No DOM element sits there, so it may be a headless-Chromium/WebGL compositing artefact. Worth a 10-second check in a real browser.

#### B3 (P2). The Background pane mixes two jobs (15, 16)

Area fill (wireframe, partial, full) and Highlight changes are about how _OSM data_ draws, not about the background. iD keeps them in a separate "Map Data" pane. Fixes:

- Move them, plus the new colour settings (QoL), into a **Map data** pane.
- In the Background pane, hide the imagery offset when no imagery is chosen, rather than showing a disabled block.
- Give the three offset inputs labels (axe: `aria-input-field-name`, serious).

#### B4 (P2). Level switcher is confusing (11, 12)

- It shows the current level as an `output` ("0") and again in the list, highlighted only by a 1.09:1 fill. Remove the duplicate output, or turn it into a header like "Level 0 · Ground".
- The switcher lists only the levels in view, so −1 appeared at the zoom the building opened at (02) and vanished after zooming in (11). Meanwhile the side panel lists Level 1 and Level 0. A building's levels jumping in and out of the switcher is confusing; list the building's levels whenever a building is entered.
- `max-w-20` truncates named levels to a number. The full name is only in a tooltip.

#### B5 (P2). Inspector order (18, 19)

- **Level** is the last field, after Website and Brand, and it's set in monospace. For an indoor editor, put Level (and Repeat on levels) right under the preset, always.
- Tags (9) and Measurements start collapsed. Remembering the open/closed state per section (as iD does) would help.
- In the preset list, presets without an icon (Indoor Stairwell, Area) have no placeholder, so their names don't line up (19).

#### B6 (P3). Smaller organisation points

- "Edit indoor here" vs "Edit indoor" is hard to tell apart. "Edit indoor (no building)" or a tooltip on first use would help.
- The building pill truncates the name ("Inside Centre Commercial ...") at the width where most building names are long. The side panel already shows the full name.
- The floor plan panel has both a "Close" text button and the toolbar toggle, and closing paths differ from the building panel's "×".
- Units default to the browser's locale, so en-US shows feet and inches in a French mall (14). Show the unit system in the measure label's tooltip, and consider defaulting from the map's country.

### C. Legibility and labelling

- **(P2) Icon-only tools.** Draw tools and all selection operations are icons. Tooltips name them, but several icons are ambiguous at 16px: square corners (□) vs offset (▣) vs square to frame (⊞), straighten (○, an octagon), symmetric, cut out. Show text labels in the contextual selection bar, and offer a "Show tool labels" setting.
- **(P2) Hint pills wrap** into a two-line `rounded-full` capsule at desktop width (14). Use `rounded-lg` once the text wraps, or shorten the copy: "Click two corners, or type width;depth ⏎ · Tab: from a side".
- **(P3) Monospace values** in the Level field, and the tiny `⌘` key hints in the Guides pane ("Place a guide M"), are 10–11px.
- **(P3) Viewer floor-numbering chips** ("G, 1, 2…" and "1, 2, 3…") have no visible label, only `title`s (25). Add a small "Floors:" label or put the choice in a menu.
- **(P3) All three pages share the `<title>`** "IndoorID" (WCAG 2.4.2). Use "Edit · Grand Quartier · IndoorID", "View · IndoorID" and "Help · IndoorID".
- **(P3) The Help page's `h1` is the app name,** and "How to use IndoorID" is an `h2`. Make the page heading the `h1`.

### D. Keyboard, focus and screen reader

- **(P1) Tab order vs visual order.** Measured order: header (6) → map canvas → locate/zoom/compass/attribution (10) → side panel → search → scope pill → shortcuts → draw tools → snap → Floor plans → Background → Guides → levels. Fixes:
  - Put the toolbar before the map in the DOM, or use `order`/landmarks.
  - Add skip links ("Skip to map", "Skip to side panel").
  - Make each toolbar a `role="toolbar"` with arrow-key roving focus, so each group costs one Tab.
- **(P2) Landmarks.** The side panel, toolbars and right panes aren't landmarks. Only the header, nav, main and the map canvas are. axe flagged the snap popover's content as outside landmarks. Fixes: `aside aria-label="Feature editor"` for the panel, `aside` for the right panes, and `role="toolbar"` with names for the rows.
- **(P2) Disabled operations explain themselves only on hover.** The toolbar uses `aria-disabled`, which is good, but the reason is only in the tooltip, and in the context menu only in a `title` attribute. Add `aria-describedby` pointing at the reason.
- **(P2) No way to select a map feature without a pointer.** This is normal for map editors, but a cheap win is "Select next/previous feature in view" (Tab / Shift+Tab while the map has focus, or `[` `]`), plus a "find room on this level" search like the viewer's.
- **(P3) Motion.** The app doesn't check `prefers-reduced-motion`. Map transitions that fly the camera and the tw-animate zoom-ins should respect it.

### E. Touch and small screens

The touch targets are mostly ≥24px. The only flagged targets were 15–16px attribution links, the 16px-tall Licenses link and a 12px-wide panel resizer handle.

- **(P2) Phone layout (24, 25).**
  - The header doesn't wrap: the version string wraps to three lines, and Language and Theme leave the screen.
  - The viewer's place search overlaps the Background button.
  - The editor is desktop only, so this is about the **viewer**. Hide the version below `sm`, put the nav in a menu, and turn the side panel into a bottom sheet.
- **(P3) The snap menu's ▾ button is 24px wide,** at the minimum.
