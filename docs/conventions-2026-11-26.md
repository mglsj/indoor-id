# Indoor conventions IndoorID could adopt (audit, 2026-11-26)

> **2026-11-26, adopted as phase W4** (one PR). Decision taken with the user: staircases are written in both forms, `indoor=room` (or `indoor=area` when open) + `room=stairs` + `stairs=yes`.

Short answer: the biggest source of new conventions this year is not the forum but the **Indoor OSM Workshop in Berlin (11–12 July 2026)**, whose decisions were written into Simple Indoor Tagging (SIT) by Tordanik and CommanderStorm between 26 June and 27 July. Earlier research (`research/osm-simple3d-editor.md`, `tagging-gaps/report.md`) never read that page. It changes four things IndoorID writes today:

1. **Entrances should not get `indoor=door`.** IndoorID's point tool writes `entrance=yes` + `door=yes` + `indoor=door`; SIT now says entrances are tagged with `entrance=*` _instead of_ `indoor=door`.
2. **`repeat_on` is for nodes only.** SIT's table lists it for nodes (doors, windows); IndoorID's Repeat dialog offers it for rooms and areas too.
3. **Elevator shafts are `highway=elevator` + `indoor=room`** in SIT. IndoorID's Elevator preset (iD's `indoor/elevator`) writes `elevator=yes`, which routers don't read.
4. **Level values like `3-5`/`5-3` or `1;2;1`** should be read as equal (IndoorID already does) **and flagged** by validators (IndoorID doesn't).

The workshop also settled stairs (centre line plus optional `area:highway=steps`, landings implied), windows (nodes in walls) and columns, and rejected door lines. The forum since 2026-11-24 adds little for 2D. osm-simple3d-editor's 74 commits since `a547bee` are mostly mobile and entrances; the one worth copying is `colour=` on doors and walls. Nothing below needs a new tag invented by IndoorID.

## 4. osm-simple3d-editor since the last review (`a547bee` → `55dde63`, 74 commits, 2026-11-24/25)

Mostly the mobile UI, entrances and gates in map mode, building passages, label occlusion and terrain. Indoor-related:

- **`colour=*` on doors, entrances, walls and columns**, drawn in that colour (`fae09fb`, `e0ecd2f`): item 9.
- **Entrance card with the door fields** (`door`, `level`, `width`, `material`, `height`); new facade entrances get `door=yes` (`9ce0916`, `231ef3f`): item 9.
- **A plan door on a vertex shared by two building parts is inside the building**, not on the facade (`1a18fc1`, `986bd80`). IndoorID's `outer-door-no-entrance` uses building outlines and `indoor=level`, not parts, so it already gets this right.
- **Closed linear walls enclose floor area** in the storey body (`ee9fc40`, `f212b3e`): for 3D.3.
- **"Select the parent, then add a child"**: `+ Entrance` on a selected building, `+ Gate` on a fence, where the point follows that parent only (`3ef02af`, `3000671`). It's a UX idea for IndoorID's point tool (`+ Door` / `+ Window` on a selected room or wall), not a convention.
- Plans for vector tiles as a data source with an embeddable view-only mode (`55dde63`), and an `editor:mode` changeset tag (`c313a08`). Nothing to copy now.
